cover, and what still has to happen before a tag. Written 2026-11-15 on the


Started 00:57:52, finished 08:57:53. `elapsed_seconds` 28,801.4 against

## What the run left behind

- `notch-23192.log`: 1,079 bytes, startup only (process start, overlay ready,
  microphone opened, sherpa-onnx zipformer loaded at 00:57:58) and then nothing
  for eight hours. No `ERROR` or `CRITICAL` line.
- `notch-fault-23192.log`: empty. No native fault or thread dump.

A quiet log and an empty fault file are the clean outcome: no unhandled
exception and no native termination for the whole run.

## Start-up measurement

The frozen exe was launched three times on this machine, each with an isolated
`APPDATA`, and its own log timed from `Process started` to `Speech recognition
on`: 4.22 s, 3.94 s and 4.53 s. The soak run agreed at 3.84 s. These are warm
launches with the model already in the file cache, so they do not falsify the
8–9.5 second figure the release audit reported for a cold install, which README
still quotes.

## Checks

`1.6.2-checks.txt` records seventeen checks, every one exiting 0: the fourteen
the release workflow runs offscreen, plus design, quality and the system-wide
hotkey check on a real display.

They ran against `main` at `605e1fb`, not against the source the frozen tree was
built from. Between `c5ee8f2` and `605e1fb` the application code changes by one
commit, `c282d00`, which prunes old diagnostic sessions at startup; the rest is
documentation, the workflow gate and the robustness guard. A rebuild would
therefore differ from this candidate in log retention alone, and would need its
own soak: rebuilding invalidates this report rather than extending it.

`check_hotkeys` died before it could report, on a foreground window title the
console codepage could not encode. That was a defect in the harness, not in the
reader; it now prints through UTF-8 and passed. Recorded because a check that
crashes while printing is indistinguishable from a check that failed.

## Published

Released 2026-11-15 as `v1.6.2`, tagged at the commit that stamps the release,
with the installer attached and `docs/release/1.6.2-notes.md` as the release
body. GitHub reports the asset's digest as
`sha256:5922d93f448bacdac3110c4c376f09e2b8e43e72cd0c3fcbccb43f814354c0b7`,
the same hash recorded above for `dist/NotchSetup-1.6.2.exe`, so the download
is the bytes this report describes.

The build is unsigned and the release says so, beside the hash check and the
SmartScreen path. That is the alternative an earlier draft of this file left
open; a signed installer is the next artifact, not this one.

## Known issue in this build

With Windows animations turned off, leaving the editor does not commit the
script. The card lands in the same turn as the toggle, the fade back in starts
before the fade out has finished, and the handler that commits the edit and
returns the reader never runs: the editor stays open and the edit is not
stored. `main` carries the fix (`fix(ui): commit the edit when reduced motion
settles the card first`); it is not in this installer.

## The gate on a runner

The first tag built after the gates landed was also the first time any of the
checks ran on a CI runner, and the run found what a developer machine hides:

- `check_behavior` hung for seventeen minutes in the first-run guide, because
  the guide is modal and is only scheduled when this user has never seen it.
  Three checks already marked it seen; the rest relied on the build machine's
  registry. Every check that builds an overlay now states it.
- `check_voice_follow` failed a 30/70 measurement taken over two visible words,
  which is not a share of anything; the runner's line height fits a single word
  at 24pt in a 122 px card.
- `check_motion` failed five spring assertions because a runner reduces
  animation, which is the one setting that turns all of it into an instant
  appearance. It now states the machine it describes.
- The loop threw on the first failure, so each defect cost a runner pass; it
  now reports every failing check in one run, and caps each check at five
  minutes so a hang names itself instead of holding the job.

The reduced-motion failure of `check_note_clearing` was not a harness problem:
it reproduced the editor bug recorded above. That is the value of running the
checks somewhere other than the machine they were written on.

## Still outstanding

- **Signing.** `NotchSetup-1.6.2.exe` is unsigned. `packaging/sign.bat` signs
  from a certificate when `NOTCH_SIGN_CERT` is configured, but signing yields
  new bytes, so this report would no longer describe the result. The next
  signed candidate needs its own eight-hour run.
- **The tester's observations.** The monitor proves the process stayed alive and
  answered; it cannot see whether Voice and Manual, microphone loss and
  recovery, notes, theme changes and global shortcuts behaved. Those notes are
  the functional half of the evidence and are not in this file.
- **The certificate.** A tag now requires this archived report and a signed,
  timestamped `Notch.exe` and installer, and fails rather than publishing
  without them. `NOTCH_SIGN_CERT_PFX` and `NOTCH_SIGN_CERT_PASSWORD` are not
  configured in the repository, so a tagged build currently stops at the
  signing step by design.
